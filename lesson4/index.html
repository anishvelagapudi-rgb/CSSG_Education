curl practice

Run the class server yourself (node lesson4/server/server.js, then API=http://localhost:3000), or use the address from class. Predict the status code before you press Enter.

# 1. What comes back, and why? $ curl -i -X POST "$API/entries/1"
405 Method Not Allowed, with an Allow: GET, PUT, PATCH, DELETE header. You create entries on the collection (/entries), not on one entry.
# 2. Your own entry, the right token $ curl -i -X PUT "$API/entries/$ID" \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/json" \ -d '{"message":"new text"}'
400 Bad Request: “Missing field: name.” PUT replaces the whole entry, so it needs every field. To change one field, use PATCH.
# 3. Run it twice. Same answer both times? $ curl -i -X DELETE "$API/entries/$ID" \ -H "Authorization: Bearer $TOKEN"
204, then 404. The responses differ, but the server ends up in the same state (entry gone) no matter how many times you send it. That's what idempotent means.
# 4. What did the server actually receive? $ curl -X PATCH "$API/echo?x=1" \ -H "X-Hello: there" -d 'hi'
The method, path, query, every header (including user-agent: curl/… and the content-type: application/x-www-form-urlencoded that -d adds by default), and the body "hi".
