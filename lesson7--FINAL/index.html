    Add login + RLS to your project

    Every file here is built on the class boilerplate (React + Express + Supabase) and has been run. Swap notes for your own table name. Do the steps in order; each ends with a check.

    STEP 1Supabase dashboard (2 min)

    1. Authentication → Sign In / Providers → Email: make sure Email is enabled. For class, turn off “Confirm email” so sign-ups work right away (the free email sender only sends a few emails per hour). Turn it back on before you launch.
    2. Project Settings → API Keys: copy the Publishable key (sb_publishable_…) and the JWKS URL. You already have the URL and secret key from last time.

    STEP 2Make a table that has an owner (3 min)

    Paste into SQL Editor → Run. The parts that matter: a user_id column that defaults to auth.uid(), RLS on, grants, and one policy per command.

    ✅ Check: Table Editor → notes shows a green “RLS enabled” badge and 4 policies under Authentication → Policies.

    STEP 3Backend: check the token, query as the user (8 min)

    1. cd backend then npm install jose
    2. Make sure backend/.env has all four Supabase values. The JWKS URL looks like https://<project-id>.supabase.co/auth/v1/.well-known/jwks.json (the old .env.example had a typo in it).
    3. Add src/auth.js, replace src/supabase.js and src/index.js, add src/routes/notes.js.

    ✅ Check: npm run dev, then open http://localhost:3000/api/notes. You should get {"error":"Not logged in"}. That's a good sign: the bouncer works.

    STEP 4Frontend: log in, send the token (8 min)

    1. cd frontend then npm install @supabase/supabase-js
    2. Add the two new VITE_SUPABASE_… lines to frontend/.env, then restart npm run dev (Vite only reads .env at start).
    3. Add supabase.ts, AuthForm.tsx, AuthGate.tsx. Replace api.ts, main.tsx, and App.tsx (or keep your App and just call the new functions).

    STEP 5Prove it works: two users (3 min)

    STEP 6Deploy (2 min)

    • Render → Environment: add SUPABASE_PUBLISHABLE_KEY and SUPABASE_JWKS_URL.
    • Vercel → Settings → Environment Variables: add VITE_SUPABASE_URL and VITE_SUPABASE_PUBLISHABLE_KEY, then redeploy.
    • Supabase → Authentication → URL Configuration: set Site URL to your Vercel URL (used by confirmation and reset emails).

    HELPWhen it breaks

    Every request says “Invalid or expired token”

    Check SUPABASE_JWKS_URL is exactly right (open it in the browser: you should see {"keys":[…]}). If keys is empty, your project still uses the legacy JWT secret: Project Settings → JWT Keys → migrate to the new signing keys.

    List is empty, no error

    That's RLS failing closed. Either no SELECT policy, or the rows have a different user_id (e.g. old rows made before login, which have null).

    “new row violates row-level security policy”

    Your INSERT policy rejected the row. Usually the token wasn't sent (so auth.uid() is null). Check api.ts adds the Authorization header.

    “permission denied for table notes”

    That's the grants, not RLS. Run the three grant lines from step 2.

    “Email not confirmed” / no email arrives

    Turn off “Confirm email” (step 1) for class, or confirm the user by hand in Authentication → Users.

    CORS error after adding login

    Restart the backend. CORS_ORIGIN must match your frontend URL exactly. The Authorization header is allowed by default.

    Logged in, but the API says “Not logged in”

    Your frontend is still using the old api.ts, or a fetch somewhere doesn't go through request().
